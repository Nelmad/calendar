## Дизайн

Разделение по архитектуре: чистое ядро решает, что показывать; React-слой только измеряет и переносит focus; private primitive даёт modal-эффекты.

- **Resolver ([`core/responsive.ts`](../../src/v02/core/responsive.ts)).** `layoutForWidth` — точная граница §7: `< breakpoint` mobile, `≥` desktop (639/639.99 → mobile, 640 → desktop). Валидная ширина — только положительное конечное число. `resolveLayout`: forced значение используется напрямую; `auto` берёт последнее валидное измерение, до него — mobile. Исключение: runtime-переход forced → auto сохраняет прежний forced layout до первого измерения, чтобы не было промежуточного passive switch. `resolveAgendaPresentation`: desktop → popover, mobile + auto → inline, mobile + overlay → sheet.
- **Измерение ([`useResponsiveLayout.ts`](../../src/v02/calendar/useResponsiveLayout.ts)).** Две половины. Render-половина хранит только state и не читает DOM/`window`/`matchMedia`, поэтому сервер и первый client render `auto` всегда mobile. Commit-половина — client layout effect: синхронное чтение content-box ширины корня (computed style минус padding/border) до paint и ровно один `ResizeObserver` на корне (`contentRect.width`). Forced layout и contract shell observer не создают. Нулевая/неизмеримая ширина игнорируется: до первого измерения mobile, после — последняя валидная ширина против текущего breakpoint. Это решение для формулировки §7 о неизмеримой ширине: скрытый календарь сам не переключает presentation. Корень без layout box неизмерим; его specified computed width не используется (раунд 2). В mobile отключено измерение строк Month, лишнего observer нет.
- **Транзакция presentation ([`core/responsive.ts`](../../src/v02/core/responsive.ts) `openOverlay`).** Состояние: `mounted` — overlay, смонтированный последним commit; `owner` — presentation, чей owning stack держит focus (вытеснение на `body` при удалении узла тоже считается). `owner` — React state, поэтому решение принимается в render: старая поверхность размонтируется, а новая монтируется в одном commit. Overlay остаётся открытым, только если resolved presentation не изменилась (desktop `auto ↔ overlay` — тот же DOM-узел) или focus внутри owning stack. При внешнем focus старый overlay закрывается, новый не монтируется. Inline всегда единственная inline-повестка.
- **Логические ключи focus.** `FocusKey`: item + control, heading, close или сам контейнер повестки, плюс показанная дата. После switch effect ставит focus на тот же control новой presentation. Если его нет (например, close при переходе в inline), применяется §12.3: ячейка даты → roving → status → toolbar → root. Overlay без логического control не открывается: восстановление ждёт его удаления. Ownership снимается при focusin вне повестки или по завершённому click, который увёл focus наружу (в том числе на `body`). Жест без смены focus, например touch-scroll, ownership сохраняет.
- **Pending acceptance ([`acceptanceRule`](../../src/v02/core/responsive.ts)).** Intent T12 переживает passive resize и смену props. В момент принятия открывается presentation, разрешённая текущим layout, ровно один раз и по своему правилу: popover — первый control; sheet — heading для pointer и Enter; inline — Enter на heading, tap оставляет focus на ячейке и объявляет `agendaUpdatedAnnouncement`, если focus внутри Calendar вне повестки. Флаг `accepted` фиксирует проверку origin до монтирования overlay: `inert` sheet снимает focus с исходной ячейки раньше второго commit. Отмены T12 (focus, unrelated key/pointer activation, Escape, уход, external/stale value) действуют как прежде. Pointer отменяет intent только завершённой activation (`pointerup`/click); touch-scroll заканчивается `pointercancel` и intent не отменяет (§7, раунд 1).
- **Sheet ([`primitives/ModalSheet.tsx`](../../src/v02/primitives/ModalSheet.tsx)).** Используются публичные блоки React Aria, из которых собран RAC Modal: `Overlay` (`disableFocusManagement`), `useModalOverlay`, `FocusScope contain`. Отсюда reference-counted `inert` (`ariaHideOutside`), reference-counted scroll lock (`usePreventScroll`) и dismissal по backdrop. Сам `ModalOverlay` не подходит: он всегда восстанавливает focus в следующем кадре, что гоняется с passive switch и с §12.3 пакета. Escape принадлежит слоистой keyboard-модели пакета. После закрытия восстановление выполняется только после удаления sheet, когда фон уже не `inert`.
- **ARIA.** `aria-haspopup="dialog"`/`aria-expanded` есть только у ячеек для popover и sheet. `aria-controls` ставится, только когда ячейка и overlay в одном tree scope. Inline — именованный `region`, sheet — именованный `dialog` с `aria-modal="true"`. `data-presentation` содержит resolved значение.
- **Surface alpha.2.** [`surface.ts`](../../src/v02/surface.ts) принимает `mobileBreakpoint` и `agendaPresentation`, допустимые layouts — `'auto' | 'desktop' | 'mobile'`. Отсутствующий `layout` означает `'auto'`, неизвестный — contract error `layout: Unsupported in 0.2.0-alpha.2; expected 'auto' or 'desktop' or 'mobile'`. [`public.ts`](../../src/v02/public.ts) делает `layout` optional и экспортирует `CalendarAgendaPresentation`. `portalContainer`, actions, sources и slots по-прежнему удаляются с warning (T16–T18).

## Исправления после проверки, раунд 1

Независимая проверка нашла два поведенческих дефекта и шесть замечаний к evidence и процессу. Исправления — от корневой причины. Регрессионные tests падают без исправлений: три в jsdom, четыре Chrome checks в Document/ShadowRoot (проверено временным откатом).

- **V1-01 (P1), focus после удаления item в sheet.** Сфокусированный item удалялся, sheet закрывался, focus уходил на корень вместо ячейки даты (§12.3, шаг 3). Причина — два effect одного commit. `MonthSurface` откладывал восстановление до удаления sheet. Затем generic recovery controller видел удалённый узел и focus на `body`. Фон ещё был `inert`, поэтому ячейка и toolbar отклонялись, и срабатывал fallback на root. На следующем commit отложенное восстановление уже не видело вытеснения. Теперь generic recovery [`useCalendarController.ts`](../../src/v02/calendar/useCalendarController.ts) уступает, пока смонтирована modal-поверхность view (`aria-modal`): восстанавливает view после удаления sheet. Если view этого не сделала, controller восстановит focus на следующем commit, когда фон уже не `inert`. Tests: [`responsive.test.tsx`](../../src/v02/calendar/__tests__/responsive.test.tsx) «removing the focused item closes the sheet…» (StrictMode, нет `inert`/backdrop); Chrome — «removing the focused item closes the sheet and restores the date cell» в Document и ShadowRoot.
- **V1-02 (P2), touch-scroll отменял pending request.** Любой `pointerdown` отменял open/focus intent, в том числе начало прокрутки. §5.2.1 отменяет intent только при *activation*, §7 запрещает перехватывать прокрутку. Отмена через `pointerdown` удалена из [`CalendarMonth.tsx`](../../src/v02/calendar/CalendarMonth.tsx). Завершённая activation по-прежнему отменяет intent через `pointerup` в capture-фазе: он срабатывает раньше click-обработчика ячейки, которая ставит новый request. Перенос focus отменяет intent через `focusin`. Tests: touch-scroll между tap и acceptance — sheet открывается один раз с focus на heading, inline объявляет ровно один раз; завершённый `pointerup` без смены focus по-прежнему отменяет intent. Chrome: CDP touch-drag (`pointercancel`, без `pointerup`/click) между tap и controlled acceptance — один sheet, затем одно inline-объявление, по одному callback на tap. Замечание без изменения: navigation intent T10 (`cancelNavigation`) по-прежнему отменяется на `pointerdown`. §5.1.1 говорит «пользовательское keyboard/pointer action», а не activation, и проверка его не затрагивала.
- **V1-03 (P2), R54.** Пункт «explicit dark применяется также к portal» включает consumer `portalContainer` и portal mirror (T16, тот же milestone alpha.2). Строка возвращена в `in_progress` с частичным evidence.
- **V1-04 (P2), устаревшие hash.** Регрессии Month/agenda перезапущены на финальном коде в новые каталоги. Прежние прогоны сохранены как попытки.
- **V1-05 (P3), story.** Добавлена `Responsive.stories.tsx`, только публичный `@nelmad/calendar`. Проверена в собранном Storybook в Chrome: четыре story рендерятся без page errors, sheet открывается по tap.
- **V1-06 (P3), SSR warning в jsdom.** Принято и задокументировано в [`useResponsiveLayout.ts`](../../src/v02/calendar/useResponsiveLayout.ts). Предупреждение React 18 появляется только при `renderToString` в среде с `document` (jsdom-tests): 13 из 245 предупреждений от `CalendarShell`, остальные 232 — от React Aria (`Hidden`, `DOMElement`), у которого тот же переключатель `typeof document`. Node/Next SSR не имеет `document` и молчит, React 19 этого предупреждения не выдаёт. Определить серверный render и при этом не сменить тип hook между hydration и client render нельзя без отказа от измерения до paint.
- **V1-07 (P3), перезапись evidence.** [`contracts.mjs`](../../scripts/implementation/contracts.mjs) принимает `--output=<dir>` (`reference/` и `public/` по версии компилятора). Без него отчёты пишутся в новый временный каталог, путь печатается. Обычный `npm run typecheck:contract` больше не трогает `docs/`, проверено `find -newer`. [`verify-foundation.mjs`](../../scripts/implementation/verify-foundation.mjs) передаёт `--output` в свой каталог `types/`.
- **V1-08 (P3), §11.3 и overlay.** Поведение не менялось, нужно решение lead. Сейчас при `layout="auto"` + `agendaPresentation="overlay"` сервер и первый client render показывают компактный mobile month с закрытым sheet, без inline-повестки: §7 разрешает явный выбор overlay на mobile в sheet. Буквальное прочтение «month+inline-agenda» потребовало бы inline-повестку на сервере и её удаление при hydration. Строка `S11.3-d7f1a73a5793` переведена в `in_progress` с записанной интерпретацией.

## Исправления после проверки, раунд 2

Повторная независимая проверка (дефекты T15-V1-01…03) нашла ошибку измерения скрытого корня и два вопроса к прочтению спецификации. Исправления — от корневой причины; регрессионные tests падают без исправления.

- **T15-V1-01 (P1), скрытый корень считался измеренным.** Синхронное чтение до paint брало `getComputedStyle(root).width`. Для элемента без layout box (предок с `display: none`, например неактивная вкладка) Chrome возвращает не used, а specified значение: `900px` для `style={{width: 900}}`, `800px` для `50em`, `100%` по умолчанию (после padding оставалось 68 px). Поэтому скрытый `auto` с px/em шириной становился desktop при hydration, а уже измеренный desktop переходил в mobile при смене `mobileBreakpoint` или forced → auto. Теперь [`useResponsiveLayout.ts`](../../src/v02/calendar/useResponsiveLayout.ts) считает корень неизмеримым, если у него нет box (`getClientRects().length === 0`) или computed width не в px. `ResizeObserver` такого корня сообщает 0 — это тоже не измерение. Хук хранит последнюю валидную *ширину*, а не только layout. При смене breakpoint, пока корень скрыт, сравнивается она: 1000 px против 700 — desktop, против 1200 — mobile. Specified ширина не участвует. Так прочитана фраза §7 о последнем валидном измерении: это ширина, а layout выводится из неё по текущему breakpoint. Описание в [`api.md`](../api.md)/[`api.ru.md`](../api.ru.md) уточнено.
- **T15-V1-03 (P3), carry-over forced → auto при неизмеримой ширине.** Решение: carry-over живёт только до commit-time чтения в layout effect того же commit. Валидная ширина заменяет его до paint, без промежуточного commit. Неизмеримый корень сбрасывает его в mobile, как требует §7 («неизмеримая ширина… остаётся mobile до valid measurement»). Скрытый календарь не может держать focus, поэтому этот переход ничего не открывает и focus не трогает. Комментарий [`resolveLayout`](../../src/v02/core/responsive.ts) обновлён.

## Исправления после проверки, раунд 3

Третья независимая проверка (T15-V2-01…04) нашла сброс выбранной пользователем agenda date при смене today, расхождение двух половин учёта ширины и устаревшие ссылки на evidence. Исправления — от корневой причины; регрессионные tests и Chrome checks падают без исправления.

- **T15-V2-01 (P1), R56: activation самой fallback-даты не записывалась.** Пока пользователь не выбрал дату, неконтролируемая повестка помечена `untouched` и следует за более поздним известным today (§5.2.1).
