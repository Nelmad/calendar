## Исправления

### 1 (P1). Путь npm cache в harness

Причина: [`packed-harness.mjs`](../../scripts/implementation/packed-harness.mjs) задавал всем вызовам npm
`npm_config_cache: '/private/tmp/calendar-npm-cache'`. `/private` есть только на macOS; на ubuntu-latest пользователь
`runner` не может создать такой каталог, и `npm ci` consumers завершается ошибкой.

Исправление: cache лежит в `os.tmpdir()` (`calendar-npm-cache`); `CALENDAR_NPM_CACHE` позволяет задать другой путь.
Локальный прогон packed тоже использовал новый путь (холодный cache, установка из registry).

### 2 (P2). Focus после ухода пользователя из Calendar

Причина: [`useCalendarController.ts`](../../src/v02/calendar/useCalendarController.ts) обновлял `lastFocus` только по
`focusin`. Нажатие на нефокусируемое содержимое страницы переводит focus на `body` без `focusin`, и `lastFocus` продолжал
указывать на последний control Calendar. Позднее обновление, которое удаляло или отключало этот control, выглядело для
эффекта commit как вытесненный focus (`unavailable && active === body`), и §12.3 переносил focus в ячейку или в область
состояния. `CalendarMonth` для своего стека этот случай уже обрабатывал (`forget()` по нажатию).

Исправление: обработчик `pointerup` в фазе capture сбрасывает `lastFocus`, если после нажатия активный элемент вне Calendar
(не в корне и не в overlays этого Calendar), в том числе `body`. Жест, который не меняет focus (прокрутка касанием,
нажатие с `preventDefault` на `mousedown`), ничего не сбрасывает. Recovery для focus, который был внутри удалённого control
(§12.3), не изменился.

Tests: [`controller.test.tsx`](../../src/v02/calendar/__tests__/controller.test.tsx), «focus the user moved out of the
Calendar» — loading/error initial после нажатия на пустое место, удаление строки inline-повестки, плюс контроль: нажатие
внутри Calendar сохраняет recovery. Chrome (review2 (`evidence/review-2026-10-09-2/review2/browser.json`)): три сценария
«§12.3 …» (mobile inline, desktop loading и error, `scrollY` не меняется) и контрольный сценарий.

### 3 (P2) и 13 (P3). Модальное окно хоста без `aria-modal` и блокировка прокрутки

Причина 3: [`modality.ts`](../../src/v02/calendar/modality.ts) считал слоем хоста только модальный `<dialog>` и элемент с
`aria-modal="true"` (решение QA-B-1-03). `ModalOverlay` React Aria Components не выводит `aria-modal`, а делает всё вне
своего overlay `inert` (`ariaHideOutside`). Sheet делал overlay хоста фоном (`inert`), React Aria делал `inert` фон
sheet: focus оставался на `body`, Tab не работал, `Escape` по displaced focus закрывал нижний sheet.

Причина 13: `lockScroll` восстанавливал снимок без согласования с блокировкой хоста. React Aria `usePreventScroll` тоже
снимает снимок (уже `hidden` от пакета). При закрытии в порядке не LIFO (sheet раньше хоста) пакет возвращал `''` под
открытым окном хоста, а хост затем восстанавливал `hidden` навсегда.

Исправление:

- Признак модального хоста — его эффект: если верхний слой пакета (backdrop или его предок) стал `inert`/`aria-hidden` не
  по воле пакета, хост накрыл стек. Тогда слоем хоста считается диалог (`dialog`, `role="dialog"`/`"alertdialog"`), показанный
  после открытия слоя, вне UI пакета, отрисованный и не скрытый хостом. Стек уступает ему как диалогу с `aria-modal`:
  без удержания focus, `z-index: auto`, `Escape` и focus — у хоста. Диалог, открытый до слоя (панель страницы, диалог вокруг
  Calendar), остаётся фоном. Немодальный `role="dialog"`, который не делает sheet `inert`, по-прежнему фон (QA-B-1-03).
- Наблюдатель документа видит изменения `inert` и `aria-hidden`, в том числе на собственном backdrop слоя.
- Если последний слой пакета закрывается, пока открыт слой хоста, фон (`inert` пакета) и блокировка прокрутки остаются до
  закрытия слоя хоста; затем пакет восстанавливает исходный `overflow`. Так страница не прокручивается под окном хоста, а
  после всех окон не остаётся `overflow: hidden`.

Tests: [`hosts.test.tsx`](../../src/v02/calendar/__tests__/hosts.test.tsx), настоящие `ModalOverlay`/`Modal`/`Dialog`
React Aria Components: окно хоста не скрыто, поле получает ввод, `Escape` закрывает только его, sheet возобновляется; закрытие
sheet под открытым окном (блокирующий `dataState`) оставляет `overflow: hidden` и фон до закрытия окна, затем `''`. Chrome:
сценарии «§8 …» и «§12.2 a sheet that closes under …». Существующие сценарии QA-10/QA-B-1-03 проходят без изменений.

Документация: [`api.md`](../api.md)/[`api.ru.md`](../api.ru.md), раздел `onItemPress`.

### 4 (P2). Видимый заголовок inline-повестки

Причина: `focusElement` всегда вызывает `focus({preventScroll: true})` (overlay сначала позиционируется). Inline-повестка
стоит под сеткой, часто ниже края экрана; Enter переносил focus на её заголовок вне viewport.

Исправление: [`dom.ts`](../../src/v02/calendar/dom.ts) `revealFocused` — `scrollIntoView({block: 'nearest'})` для
сфокусированного узла. Его вызывают правило приёма inline-повестки (заголовок по Enter) и восстановление §12.3 на цели,
которые не прокручиваются сами: область состояния, toolbar, корень (ячейки дат уже прокручивают себя).

Tests: [`responsive.test.tsx`](../../src/v02/calendar/__tests__/responsive.test.tsx) (один вызов на заголовке с
`nearest`); Chrome: 390×500, шапка 150 px — заголовок внутри viewport, screenshot `review2/mobile-inline-heading-revealed.png`.

### 5 (P2). Неизвестная система цифр

Причина: [`locale.ts`](../../src/v02/core/locale.ts) `localePreferences` вызывал `Intl.Locale#getHourCycles()` без защиты;
ICU бросает «Internal error» для любой неизвестной `-u-nu-` (Node 24/ICU 78.3 и Chrome 155). Тег проходит `isLocaleTag` и
`supportedLocalesOf`, поэтому исключение вылетало из render, SSR и helper.

Исправление: чтение locale info (`getWeekInfo`, `getTextInfo`, `getHourCycles`) защищено от `RangeError`; без него hour
cycle берётся из `resolvedOptions()` форматтера — одинаково в Node и браузере. Иные ошибки не глотаются.

Tests: [`locale.test.ts`](../../src/v02/core/__tests__/locale.test.ts) (`en-u-nu-xyz`, `ru-RU-u-nu-foo`, `he-u-nu-abc`:
детерминированный результат, диапазон helper равен диапазону базового тега; `TypeError` проходит наружу) и
[`surface.ssr.test.tsx`](../../src/v02/calendar/__tests__/surface.ssr.test.tsx) (SSR публичного Calendar).

### 6 (P2). Проекция длинных интервалов

Причина: `orderItems` проецировал каждый timed item целиком: `scanOffsetSpans` читает смещение каждые 72 ч всей
длительности. Item 0001…9999 в Europe/Berlin стоил 3,8 с SSR, 1000 годовых items — 424 мс только на сортировку.

Исправление в [`projection.ts`](../../src/v02/core/projection.ts) и [`layout.ts`](../../src/v02/core/layout.ts):

- `projector.dates(interval, zone)` возвращает `first`/`end` (первая и следующая за последней локальные даты) и `contains(day)`.
  Interval до 32 дней проецируется целиком, как раньше. Более длинный — только на концах: первая локальная дата лежит в
  первых 48 ч instants, последняя — в последних 48 ч, потому что смещения по модулю меньше 24 ч. Дата между ними покрыта,
  если хотя бы один её instant внутри interval (`dayInstants` даты, кэш на 512 дат). Пропуски (Apia 2011) и folds точны.
- Layout работает только с `first`/`end`/`contains`: группа «несколько дат» — `end - first > 1`, сегменты недели — серии
  покрытых колонок, продолжения — по `first`/`end`. Для двух multi-day timed items с одинаковым началом порядок «длиннее
  раньше» берётся по последней дате: при одинаковом начале даты короткого interval — префикс дат длинного, а смещения
  меняются не чаще раза в 72 ч, поэтому поздний fold не возвращает пропущенную дату.

Tests: [`projection.test.ts`](../../src/v02/core/__tests__/projection.test.ts) — совпадение с полной проекцией в Apia,
Berlin, Goose Bay (обратный переход через полночь), Lord Howe (30 мин), Etc/GMT+12 у начала и Kiritimati у конца домена;
дыра Apia; весь домен в Berlin — меньше 400 чтений смещения и 500 мс; число чтений не зависит от длительности;
[`surface.ssr.test.tsx`](../../src/v02/calendar/__tests__/surface.ssr.test.tsx) — SSR item всего домена в Berlin быстрее
1 с (было 3,8 с). Существующие layout tests проходят; projection parity (`evidence/review-2026-10-09-2/projection/runtime-parity.json`)
Node/Chrome дополнен границами `first`/`end`.

### 7 (P2) и 20 (P3). Направление текста дат и shell

Причина 7: [`formatting.ts`](../../src/v02/core/formatting.ts) записывал во fragments дат `dir: resolved.dir` — с учётом
переопределения `dir`. `<bdi dir="rtl">` с русской датой давал «.сент. 2026 г 1».

Исправление 7: fragments дат и времени получают направление письменности locale (`localeDirection(resolved.locale)`), а
`dir` остаётся направлением раскладки.

Причина 20: `contractMessages` брал направление из исходного тега, а `lang` и data state — из разрешённого locale
(`zz-Arab`, `dv` → `en-US`, но shell `rtl`). Исправление: [`messages.ts`](../../src/v02/core/messages.ts) берёт направление
разрешённого locale.

Tests: [`messages.test.tsx`](../../src/v02/core/__tests__/messages.test.tsx) — «date fragment direction» (ru-RU/en-GB/en-US
с `rtl`, ar/he с `ltr`, SSR заголовка) и shell `zz-Arab`/`dv` равен data state. Chrome: три сценария «§11.2 …» — computed
direction и визуальный порядок первого и последнего символа каждого fragment, screenshots `review2/*-dir-*-agenda.png`.

Документация: `dir` в API EN/RU.

### 8 (P3). Корень в неподключённом container

Причина: [`useRootName.ts`](../../src/v02/calendar/useRootName.ts) начинал наблюдение только после проверки `isConnected`;
отключённый при эффекте корень ничего не наблюдал, и зависимости эффекта больше не менялись.

Исправление: пока корень не подключён, наблюдается его `ownerDocument`; после вставки наблюдение переходит на дерево
корня и ссылка проверяется. Ложных предупреждений при unmount нет: проверка по-прежнему ждёт подключения.

Test: «validates aria-labelledby once a root rendered into a detached container is attached» (`controller.test.tsx`), с
последующей повторной проверкой и предупреждением.

### 9 (P3) и 10 (P3). Overlays скрытого или приостановленного владельца

Причина 9: `scrolledAway` в [`NonModalPopover.tsx`](../../src/v02/primitives/NonModalPopover.tsx) возвращал `false` для
якоря без layout box, и popover оставался видимым в начале viewport.

Исправление 9: якорь без box, для которого `checkVisibility()` ложно (предок `hidden`/`display: none`, fallback Suspense),
считается ушедшим, как прокрученный: overlay обрезается (`clip-path: inset(50%)`) и возвращается при показе. В DOM без
layout (`checkVisibility` нет) поведение прежнее.

Причина 10: React при повторной приостановке Suspense скрывает host-узлы границы и разрушает layout effects скрытого
поддерева, но не скрывает содержимое portals. Слой sheet (`openModalLayer` в layout effect) снимался, sheet оставался
видимым `aria-modal`.

Исправление 10: [`ModalSheet.tsx`](../../src/v02/primitives/ModalSheet.tsx) — если слой снят, а backdrop остаётся подключённым
после микрозадачи (не unmount и не повтор StrictMode), backdrop получает `hidden` (CSS `.nc-backdrop[hidden]`). При
повторном появлении effects снимают `hidden`, открывают слой и возвращают focus с `body` в sheet. Desktop popover обрезается
по исправлению 9.

Tests: только Chrome (jsdom не моделирует layout и скрытие Suspense): «§12.2 desktop: a popover whose host panel becomes
hidden …», «§12.2 Suspense: a sheet …» (во время приостановки нет видимого `aria-modal`, фон не `inert`, `overflow` пуст;
после — всё восстановлено, focus в sheet, `Escape` закрывает) и «§12.2 Suspense: a desktop popover …».

### 12 (P3). Перерисовка trigger строк

Причина: каждый `ItemActionsTrigger` подписывался на весь стек (`useStackVersion`); значение контекста overlays было новым
объектом на каждый render.

Исправление ([`overlays.tsx`](../../src/v02/calendar/overlays.tsx), [`CalendarMonth.tsx`](../../src/v02/calendar/CalendarMonth.tsx)):
trigger читает свою запись стека через `useSyncExternalStore` и перерисовывается только при её смене; значения контекста
мемоизированы.

Test: [`overlays.renders.test.tsx`](../../src/v02/calendar/__tests__/overlays.renders.test.tsx) — 40 строк, открытие и
закрытие одного menu перерисовывают не больше двух trigger (до исправления — 40).

### 14 (P3). Кольцо focus в списках действий и sources

### R2C-1 (P2). Focus после касания вне Calendar

Причина. Обработчик исправления 2 читал активный элемент в `pointerup`. Мышь переносит focus на `mousedown`, до
`pointerup`; касание — на совместимом `mousedown`, который идёт после `pointerup` и `touchend`. В момент `pointerup`
focus ещё в Calendar, `lastFocus` оставался, и позднее обновление (удаление строки inline-повестки, начальная загрузка)
возвращало focus в ячейку или в область состояния.

Исправление ([`useCalendarController.ts`](../../src/v02/calendar/useCalendarController.ts)): та же проверка выполняется ещё
и в фазе capture события `click`, которое при касании идёт после переноса focus (как `press()`/`forget()` в
`CalendarMonth`). `pointerup` оставлен: он покрывает нажатие второй кнопкой мыши, после которого `click` нет. Recovery для
focus, который был внутри удалённого control, не изменился.

Tests ([`controller.test.tsx`](../../src/v02/calendar/__tests__/controller.test.tsx), «focus the user moved out of the
Calendar»): касание в порядке браузера — `pointerdown`, `pointerup`, `touchend` при focus внутри, затем `mousedown`, уход
focus на `body`, `click`; удаление строки inline-повестки и начальная загрузка оставляют focus на `body`. Chrome
(review2 (`evidence/review-2026-10-09-2-fix-2/review2/browser.json`), контекст `hasTouch`/`isMobile`, `page.tap`): три
сценария «§12.3 … touch …» (mobile inline, desktop loading и error); первый записывает порядок событий
(`pointerup` и `mousedown` при focus в Calendar, `click` — на `body`). Контроль: касание сфокусированной строки сохраняет
recovery внутри Calendar.

### R2C-2 (P3). Корень, подключённый к ShadowRoot позже

Причина. MutationObserver документа не видит изменений внутри shadow tree. Корень, отрисованный в отключённый container и
вставленный в ShadowRoot, и корень, удалённый из документа и вставленный в ShadowRoot в поздней задаче, не замечали
подключения: наблюдатель оставался на документе, `aria-labelledby` не появлялся.

Исправление ([`useRootName.ts`](../../src/v02/calendar/useRootName.ts)): пока корень отключён, кроме наблюдения документа
раз в animation frame проверяется `isConnected`. После подключения `update()` переводит наблюдатель на `getRootNode()` и
проверяет ссылку. Кадр планируется, только пока корень отключён, по одному; cleanup эффекта отменяет запланированный кадр.
Без `aria-labelledby` по-прежнему нет ни наблюдателя, ни кадров (C2 проверки 1).

Tests (`controller.test.tsx`): оба варианта — отключённый корень, вставленный в подключённый ShadowRoot, и подключённый
корень, перенесённый в ShadowRoot через отдельную задачу; имя появляется, а опустевший label в ShadowRoot снимает его (наблюдатель
теперь на ShadowRoot). Ещё один test: корень, оставшийся отключённым, перепроверяет подключение по кадрам и после unmount
не планирует ни одного кадра.

Сценарий проверяющего `detached-shadow.test.tsx` читает атрибут синхронно сразу после вставки. Подключение к ShadowRoot
теперь замечается не позже следующего кадра. Вариант того же файла с ожиданием одного `requestAnimationFrame` после
вставки проходит 3/3 (`scratchpad/review2-fix2/jsdom`). Синхронного признака вставки в ShadowRoot у DOM нет: custom element

### R2C-3 (P3). Focus в модальном окне хоста с момента открытия

Причина. `ModalOverlay` React Aria Components в одном commit сначала переносит focus в свой диалог (layout effect
`FocusScope` дочернего компонента), затем делает фон `inert` (`ariaHideOutside` родителя). Обработчик `focusin` стека
видел focus вне слоя раньше, чем `inert` на sheet, и возвращал его в sheet. Затем React Aria делал sheet `inert`, и Chrome
переносил focus на `body` до повторного focus React Aria через 500 мс.

Исправление ([`modality.ts`](../../src/v02/calendar/modality.ts)):

- если focus ушёл в диалог вне UI пакета, показанный после открытия слоя, удержание откладывается на microtask — до
  конца commit, который открыл диалог. Затем стек заново классифицирует слои. Хост, накрывший стек, — слой хоста, и focus
  остаётся в нём. Немодальный `role="dialog"`, который не скрывает sheet, по-прежнему фон (QA-B-1-03), и focus
  возвращается в sheet;
- если хост накрывает стек позже, в отдельной задаче, focus, оставшийся в скрытом хостом sheet, переносится в диалог хоста,
  как focus на `body`.

Tests ([`hosts.test.tsx`](../../src/v02/calendar/__tests__/hosts.test.tsx)): `ModalOverlay` React Aria Components над
sheet — сразу после открытия и после кадров focus в диалоге хоста, журнал `focusin` содержит только диалог (без
возврата в sheet); поздний `role="dialog"` с focus остаётся фоном, а когда он затем скрывает sheet через `aria-hidden`,
focus переходит в него. Chrome: два сценария «§8 … has focus as soon as it opens …» (sheet и контрольный desktop popover)
читают focus сразу после Enter без явного `focus()` и через 700 мс, после повторного focus React Aria; журнал `focusin` —
`['host']`.

Документация: [`api.md`](../api.md)/[`api.ru.md`](../api.ru.md) — `onItemPress` (focus, перенесённый хостом в диалог в том же
commit, остаётся в нём) и `aria-labelledby` (проверка после подключения к документу или ShadowRoot, не позже следующего
кадра); CHANGELOG.

### Остаточные риски раунда 2

- Подключение отключённого корня к ShadowRoot замечается не позже следующего animation frame, а не синхронно. В фоновой
  вкладке кадры не идут, проверка выполняется при возвращении. Корень, который остаётся отключённым и смонтированным
  (кэш вида), раз в кадр выполняет одну проверку `isConnected` до unmount или подключения.
- Отложенное на microtask удержание focus (R2C-3) рассчитано на хост, который скрывает фон в том же commit, где переносит
  focus. Хост, который делает это в поздней задаче, на этот промежуток получает focus обратно в sheet; когда хост затем
  накрывает стек, focus переходит в его диалог. Немодальный `role="dialog"` (QA-B-1-03) получает удержание на microtask
  позже, чем раньше.
- Сброс памяти focus по `click` (R2C-1) не срабатывает для касания, после которого браузер не выдаёт `click` (например,
  хост отменяет `touchend`); тогда focus и не переносится. Физические iOS/Android по-прежнему не проверялись (T23).
- Firefox, Safari, физические устройства и AT не проверялись. Candidate не опубликован; npm publish и действия в registry
  не выполнялись.
