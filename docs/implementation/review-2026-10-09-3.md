## Исправления

### 1 (P2). Календарь внутри диалога хоста без `aria-modal`

Причина. По §10.3.4 (draft v7) target по умолчанию — ближайший открытый модальный контейнер (`<dialog>` после
`showModal()` или `aria-modal="true"`), а `role="dialog"` без `aria-modal` им не является. Radix Dialog и
`Modal`/`Popover`/`Dialog` React Aria Components выводят именно такой `role="dialog"` и при этом удерживают focus или
закрываются при уходе focus наружу. Повестка в `body` тогда добавляется и удаляется в одном кадре, а popover хоста
закрывается сам. Правило v7 замечание не оспаривает; не хватало диагностики и документации, а в alpha.1 popover жил
внутри корня, поэтому для пользователей alpha.1 это регресс без подсказки.

Исправление ([`portal.ts`](../../src/v02/calendar/portal.ts)): правило target по умолчанию не менялось. Если
`portalContainer` не передан, target разрешился в `body`, а на composed path корня есть `role="dialog"` или
`role="alertdialog"`, который не является модальным контейнером, сборка development один раз на календарь пишет
`[@nelmad/calendar] portalContainer: The calendar is inside a role="dialog" element without aria-modal="true", so the agenda
and menus render in document.body; a dialog or popover library that traps focus or closes on outside focus closes them (or
itself) at once. Pass that dialog element as portalContainer, or document.body to keep this default`. Явный валидный
container, в том числе `document.body`, — выбор потребителя, о нём предупреждения нет. В production проход по предкам не
выполняется. README EN/RU получил раздел «Modal and popover libraries» с примером, API EN/RU — абзац о Radix и React Aria
Components и строку таблицы диагностик, story Portals — то же в описании, CHANGELOG — запись.

Tests ([`hosts.test.tsx`](../../src/v02/calendar/__tests__/hosts.test.tsx), «Calendar inside a host dialog without
aria-modal»): `Modal` React Aria Components — одно предупреждение с точным текстом после двух открытий; панель
`role="alertdialog"` называет свою роль; явный container и `document.body` — без предупреждения, повестка открыта;
`aria-modal="true"` и календарь без диалога — без предупреждения. Chrome (review3 (`evidence/review-2026-10-09-3/review3/browser.json`)):
`Modal` и `Popover` React Aria Components 1.x (диалог проверен: `role="dialog"`, без `aria-modal`) — с target по умолчанию
повестка в хосте не работает, ровно одно предупреждение; с диалогом как `portalContainer` повестка открывается внутри него,
нажатие строки вызывает `onItemPress`, предупреждений нет. Radix в репозитории не установлен и не проверялся; его
поведение взято из воспроизведения проверяющего.

### 2 (P2) и 3 (P3). Заголовки и строка пустой повестки

Причина. `.nc-calendar-heading` задавал только `margin` и `font-size`, `.nc-day-list-heading h3` — то же, а `<p>` пустой
повестки не задавал ничего. Цвет, насыщенность, межбуквенный интервал, высота строки и отступы приходили из правил
элементов страницы или из стилей браузера. В шаблоне Vite (`h1,h2 {color: var(--text-h); font-weight: 500}` с цветом по
схеме страницы) при `colorScheme`, отличном от схемы страницы, заголовок месяца становился почти невидимым; сброс preflight
(`h1…h4 {font-weight: inherit}`, `* {margin: 0}`) снимал жирность и сжимал пустой popover со 153 до 129 px.

Исправление ([`styles.css`](../../src/v02/styles.css)): заголовок месяца и заголовки повестки/sheets со специфичностью
класса задают `color: inherit`, `font-weight: 700`, `font-family`, `font-style`, `letter-spacing`, `line-height`,
`text-transform: inherit`, `padding: 0`, `border: 0`; строка пустой повестки получила класс `nc-day-list-empty`
([`DayAgendaBody.tsx`](../../src/v02/calendar/DayAgendaBody.tsx)) с `margin: 1em 0` — ровно тот отступ, который уже
заложен в резерв `--nc-inline-agenda-size`; у строки числа событий явный `margin-inline: 0`. Правило страницы с классом
(`.prose h2`) — оформление потребителя и по-прежнему применяется; README EN/RU это говорит.

Проверки Chrome (review3): правило `h2` шаблона Vite на тёмной странице с `colorScheme="light"` и на светлой с `"dark"` —
цвет заголовка равен цвету корня, насыщенность 700, `letter-spacing: normal`, высота строки от страницы, контраст с
поверхностью календаря не ниже 4,5:1; сброс preflight — заголовки h2/h3, отступы пустой строки и размер пустого popover
совпадают с прогоном без сброса. На снимке обе проверки шаблона и проверка сброса падают.

### 5 (P2) и 11 (P3). Recovery из inline-повестки после внешней смены месяца

Причина. `recover()` в [`CalendarMonth.tsx`](../../src/v02/calendar/CalendarMonth.tsx) брал roving дату из ref
контроллера, который пишется в layout effect `CalendarShell`, то есть после layout effect `MonthSurface` (дочерние effects
выполняются раньше родительских). Для inline-повестки recovery идёт в layout effect того же commit и видел roving дату
прежнего месяца (`2026-09-10`), которой в новой сетке нет, и проваливался к шагу 6 (toolbar). Popover и sheet
восстанавливают focus в passive effect после удаления overlay, когда ref уже обновлён, поэтому там ошибки не было.

Исправление: `MonthSurface` пишет roving дату своего commit в собственный ref в layout effect, объявленный до effect
recovery; неиспользуемый `getFocusDate` контроллера удалён.

Tests ([`agenda.test.tsx`](../../src/v02/calendar/__tests__/agenda.test.tsx), «inline agenda recovery after an external
month change»): неконтролируемая повестка, focus на item, `anchorDate` → апрель и май — focus на roving ячейке
(`…-04`); контролируемая повестка с датой вне новой сетки — то же. Chrome (review3, 390 × 844): неконтролируемая
(`2026-11-01` → `2026-11-10`, `2026-10-01` → `2026-10-10`) и контролируемая. На снимке все падают.

### 6 (P3). Roving Tab stop без `today`

Причина. [`useCalendarController.ts`](../../src/v02/calendar/useCalendarController.ts) выводил начальную цель (§12.1:
agenda date → selection → today → первый день) только до первого commit; затем commit effect сохранял её как состояние
навигации, и она вела себя как сохранённая логическая дата. Первый рендер без `today` (клиент или hydration) давал 1-е
число; когда часы прочитаны, нетронутая повестка переходила на today (§11.3), а Tab stop оставался на 1-м.

Исправление: пока логическая дата не сохранена, цель выводится заново в каждом render. Сохраняют её focus на дате,
запрос навигации и внешняя смена месяца (по §5.1.1 она сохраняет номер дня, поэтому test alpha.1 «external month change
clamps the roving date» не изменился и проходит). После сохранения поведение прежнее.

Tests ([`responsive.test.tsx`](../../src/v02/calendar/__tests__/responsive.test.tsx), «initial roving target before a
saved logical date»): 400 и 900 px — Tab stop следует за поздно известным today и его сменой; контролируемая повестка —
Tab stop следует за `agendaDate`, после стрелки дата сохранена, и смена today/agenda её не двигает. Chrome (review3, fake
clock 2026-09-10 23:59 MSK, desktop и mobile): после чтения часов Tab stop = today = повестка, после полуночи — 09-11, Tab
входит в сетку на today, после стрелки следующий день дату не двигает.

### 7 (P3). Заголовки дней недели

Причина. `.nc-weekday` с `overflow: hidden` и без запасного формата: при 320 px (`ar-EG`, «الخميس» 47 px в столбце 39 px)
и тексте 200% (`Mon` 54 > 49 px) видимый текст терялся (§12.5).

Исправление: короткое название обёрнуто в `.nc-weekday-label` ([`MonthView.tsx`](../../src/v02/calendar/MonthView.tsx)),
узкое (`weekday: 'narrow'`, [`formatting.ts`](../../src/v02/core/formatting.ts)) записано в `data-narrow-label`.
`useWeekdayFit` ([`useMonthMeasurements.ts`](../../src/v02/calendar/useMonthMeasurements.ts)) в layout effect и по
ResizeObserver строки и самих коротких названий (смена размера текста) сравнивает computed ширину каждого названия с
шириной содержимого столбца и, если хоть одно не помещается, ставит строке `data-narrow-weekdays`: CSS показывает узкие
названия через `::after`, а короткие остаются в layout скрытыми, поэтому проверка не зависит от своего результата. Пишется
только атрибут, без render; серверный HTML прежний (короткие названия). Полные названия остаются accessible names;
`text-overflow: ellipsis` отмечает обрезку, если не поместится и узкий формат.

Tests ([`month.test.tsx`](../../src/v02/calendar/__tests__/month.test.tsx), «grid description and weekday fit»):
ширины computed style подменены — широкое название включает узкий формат (`ar-EG`, узкие названия, полное имя и текст
четверга сохранены), помещающееся — нет. Chrome (review3): `ar-EG` 320 px и `en-US` 390 px с текстом 200% — каждое видимое
название помещается (узкий формат), `en-US` 390 px — короткие названия; screenshots `weekdays-*.png`.

### 9 (P3) и 15 (P3). Обещание о `tokens`

Причина. Правило безопасности (§10.3.2, v7) отклоняет любой `url(`, включая экранированные записи; код ему соответствует.
README и API утверждали шире: значение «не может сослаться на ресурс». Строковые формы `image-set("…" 1x)`,
`-webkit-image-set(…)`, `image("…")`, `src("…")` принимаются и становятся наследуемыми переменными; собственные стили
пакета используют переменные только в свойствах цвета, тени и шрифта и ничего не загружают, но CSS потребителя или slot с
переменной в свойстве изображения загрузил бы ресурс.

Исправление: README и API EN/RU сужены до `url(` и прямо называют строковые функции и границу ответственности
(проверять значения арендаторов, если переменные используются в свойствах изображений). Правило не расширялось: это
изменило бы норму §10.3.2 и требует решения владельца спецификации.

### 10 (P2). Блокировка прокрутки и `layout="auto"`

Причина. `lockScroll` в [`modality.ts`](../../src/v02/calendar/modality.ts) ставил `scrollbar-gutter: stable` и
`overflow: hidden` на `<html>` и не проверял результат. На платформе с overlay scrollbars (macOS) страница со
`::-webkit-scrollbar` получает классическую полосу 17 px, а под `overflow: hidden` Chrome не держит для неё stable gutter:
ширина содержимого росла на 17 px, корень 626–636 px пересекал 640, календарь переключался в desktop, sheet закрывался,
повестка открывалась popover, а sheets действий и sources не открывались. Отладка показала ещё одну причину: `clientWidth`
у `<html>` для такой полосы устаревает внутри одной задачи (блокировка снята и взята снова — StrictMode) и не учитывает
stable gutter, поэтому измерение полосы по `clientWidth` давало 0 и gutter не ставился вовсе.

Исправление: полоса и её потеря измеряются по box `<html>` (`getBoundingClientRect().width` с вычетом margins), а не по
`clientWidth`. Если после `overflow: hidden` box расширился, добавленная ширина компенсируется `padding-right` (к
собственному padding страницы); при сохранённом gutter (нативные классические полосы) ничего не добавляется.
Восстановление прежнее. Одно принудительное вычисление layout на блокировку.

Tests ([`hosts.test.tsx`](../../src/v02/calendar/__tests__/hosts.test.tsx), «scroll lock keeps the layout width»):
потерянный gutter → `padding-right: 17px` и полное восстановление; сохранённый → без padding; собственный padding страницы
8 px → 25 px. `clientWidth` в tests намеренно устаревший, как в Chrome. Chrome (review3, viewport 680, корень на полосу ниже
640 px): стилизованная полоса на overlay-платформе и нативная классическая, для sheets повестки, действий и sources —

### 12 (P3). Данные locale для SSR

Причина. README называл только `az-Arab`. Сравнение проверяющего (Node 24.20, ICU 78.3, против Chrome 155) нашло 96
языков, которых нет в Chrome, и 8 с разным текстом; браузер разрешает такие locales в `en-US`, сервер выводит родной текст,
hydration не проходит, а при других данных недели (`ps-AF`) различаются первый день недели и видимый диапазон.
§11.3 не обещает одинаковый результат при разных данных Intl; это пробел документации.

Исправление: ограничение «SSR locale data» в README EN/RU описывает механизм, последствия для `getCalendarVisibleRange`,
примеры языков и способ проверки (`Intl.DateTimeFormat.supportedLocalesOf` в браузере или client-only рендер). Серверной
диагностики нет: сервер не знает Intl браузера.

### 14 (P3). `+N` в узком столбце

Причина. `.nc-overflow` с `overflow: hidden` без `text-overflow`: при 64 px и шрифте 24 px «+1,200» выглядел как «+1,20».

Исправление ([`styles.css`](../../src/v02/styles.css)): `white-space: nowrap; text-overflow: ellipsis` — обрезка видна
(«+1,…»). Полное число остаётся в описании ячейки и в повестке. Проверки Chrome (review3): 1200 items, 480 px, 24 px,
en-US и ar-EG — computed `text-overflow: ellipsis`; screenshots `plus-n-*.png`.

## Остаточные риски

- Предупреждение замечания 1 срабатывает на любом `role="dialog"`/`"alertdialog"` без `aria-modal` вокруг календаря,
  в том числе на боковой панели без удержания focus; для неё документирован `portalContainer={document.body}`.
  Хосты, которые удерживают focus без `role="dialog"`, предупреждения не получают. Radix Dialog не проверялся в этом
  репозитории (только React Aria Components).
- Компенсация блокировки (10) — `padding-right` на `<html>`: fixed-элементы страницы с `right: 0` под sheet сдвигаются на
  ширину полосы так же, как при нативной полосе; измерение по box `<html>` не учитывает `zoom`/`transform` на самом `<html>`.
  Проверено в Chrome на macOS (overlay-платформа со стилизованной полосой и нативные классические полосы с отключёнными
  overlay scrollbars); Windows, Firefox и Safari не проверялись.
- Узкий формат дней недели (7) переключает всю строку, если не помещается хоть одно название; в en-US узкие названия
  неоднозначны (T/T, S/S), полные остаются accessible names. Если не помещается и узкий формат, остаётся многоточие.
- `+N` (14) теперь видимо обрезан, но число всё ещё не видно полностью в столбце 64 px при очень крупном шрифте и
  четырёхзначном счёте; полное число — в описании ячейки и в повестке.
- Новое правило сохранённой даты (6): до первого focus/навигации Tab stop следует за контролируемой `agendaDate`; это
  соответствует порядку §12.1, но меняет прежнее поведение (раньше начальная цель фиксировалась при первом commit).
- Размер bundle (13) — открытый риск релиза.
- Firefox, Safari, физические устройства и AT не проверялись (матрица RC). Candidate не опубликован; npm publish и действия
  в registry не выполнялись.
