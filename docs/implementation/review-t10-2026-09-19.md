## Замечания

1. **P2 — focus теряется при возвращении из blocking state.** В `src/v02/calendar/useCalendarController.ts:85` recovery выполняется только при `model.blocking`. В Chrome: focus на `2026-04-15` → `loading/initial` корректно переводит его на видимый loading region → `ready` удаляет region и оставляет focus на `body`. То же после `error/initial`, в Document и ShadowRoot. `lastFocus.surface` у status равен `other`, поэтому navigation kernel тоже не восстанавливает его. Нужен recovery удалённого status/control в текущую roving cell по §12.3, с сохранением внешнего focus.

2. **P2 — PageUp/PageDown не всегда запрашивают другой месяц.** В `src/v02/core/controller.ts:32` все grid-команды при target внутри visible range выполняют немедленный focus без `onNavigate`. В March 2026, en-US, `PageDown` с 1 марта переводит focus на видимое 1 апреля, но heading остаётся March и callback отсутствует. Обратный случай: `PageUp` с 30 апреля переводит focus на 30 марта без запроса. По §5.1.1 эти команды должны запросить предыдущий/следующий отображаемый месяц и ждать acceptance. Controller должен различать перемещение по датам и явную смену месяца, сохраняя для обоих источник focus intent `grid`. Воспроизводится через текущую fixture; полноценный Month View ещё не реализован.

3. **P2 — ARIA labels теряют фактический язык сообщения.** В `src/v02/calendar/CalendarShell.tsx:37` и аналогичных местах используется только `.text`. При `locale="ar"` built-in fallback создаёт английские `Previous month`, `Next month`, `Calendar`, `Could not load calendar`, однако именуемые элементы наследуют `lang="ar"`. Внутренний visible error text корректно имеет `lang="en-US"`, но это не меняет язык `aria-label` его parent region. Нужно сохранять `LocalizedText.lang` также при формировании accessible names (§11.2). Проверены DOM language attributes; произношение реальным скринридером не квалифицировалось.

4. **P2 — valid root label может быть отвергнут.** Самодельный `contribution()` в `src/v02/calendar/dom.ts:42` учитывает DOM text/attributes, но не полное accessible-name contribution. В Chrome same-tree label с `#own-label::before { content: "Project calendar" }` даёт native accessible name `Project calendar`. Controller считает target пустым, удаляет `aria-labelledby` и заменяет это имя общим fallback. Проверка через Chrome Accessibility tree подтверждает оба результата. Нужен совместимый расчёт contribution, включая generated content, и соответствующая browser regression. Проверка одного только `textContent` не достаточна для контракта §5.7.
